# C32: C inside the game's 32-bit segment (`host/c32/`)

C32 is **C99 compiled for i386** and linked into one flat image that the loader maps below
4 GB. From then on it is ordinary 32-bit code in the same code segment as `gta2.exe`
(selector `0x87`): game pointers are real C pointers, `re/gta2_types.h` structs are used
as they are, game functions are called with a plain `call`, and a game call site can jump
straight into a C32 function — no mode switch, no `call32`, no NASM stub per hook.

The other C flavour is 64-bit host C (`host/c/`, `docs/host-c.md`), which reaches the game
through `call32` and memory accessors. The split (user decision after the two pilots, Seq 53
= 64-bit, Seq 54 = C32, 2026-10-22): **game logic** — mods, detours into game functions — is
C32; **host features** — K menu, config, SDL, logs — are 64-bit host C. So a C32 mod's
config key and K menu row live in `host/c/c32_host.c`.

## Memory map

| Range | What |
|---|---|
| `0x003F0000-0x0067A000` | `gta2.exe` image |
| **`0x0F000000-0x0F100000`** | **C32 image** (`C32_BASE`, `C32_MAX` = 1 MB incl. bss; `host/c32/c32.ld`) |
| `0x10000000-0x11000000` | low region: thunks, import stubs, TEB, JMPHOOK trampolines, 32-bit stack (`loader.asm`) |
| `0x20000000-0x60000000` | shim arena: heap, `low_alloc` (`w32_core.asm`) |
| `0x7F000000-` | fake HMODULEs, never mapped |

The image is mapped `rwx` with an mmap **hint**, not `MAP_FIXED` (which would silently
replace whatever is there): any other address back means the range is taken and the loader
stops with `c32: FAIL: 0xf000000-... is taken`.

## Build

`host/build.sh` does it before assembling `loader.asm`; every `host/c32/*.c` is picked up:

```sh
clang -target i386-pc-none-elf -march=i686 -std=c99 -ffreestanding -fno-pic \
      -fno-stack-protector -fno-asynchronous-unwind-tables -mno-sse -mno-mmx \
      -mstack-alignment=4 -freg-struct-return -O2 -Wall -Wextra -Werror -c x.c
ld.lld -m elf_i386 -T c32/c32.ld -Map c32/c32.map -o c32/c32.elf *.o           # symbols
ld.lld -m elf_i386 -T c32/c32.ld --oformat binary -o c32/c32.bin *.o           # the image
```

- **`ld.lld`** is required (`brew install lld`, arm64 Homebrew; 23.1.4 measured): Apple `ld`
  cannot link i386. `LLD=/path/to/ld.lld` overrides; the build stops with
  `no ld.lld (brew install lld)` without it. Apple clang compiles i386 ELF on its own.
- `loader.asm` embeds `c32/c32.bin` (`incbin`, `host/c32_blob.asm`). `c32/*.o`, `.elf`,
  `.bin`, `.map` are git-ignored build output.
- Why each flag: `-mno-sse -mno-mmx` — floats stay on x87 like the game's (MSVC 6 era) and
  nothing touches the XMM state; `-mstack-alignment=4` — game code only keeps `esp` 4-aligned,
  clang's i386 default assumes 16; `-freg-struct-return` — 8-byte structs come back in
  `edx:eax` like MSVC, not through a hidden pointer; `-fno-pic` — fixed address, plain
  absolute references.
- What is in the image: `c32/c32.map` (or `xcrun llvm-objdump -d --x86-asm-syntax=intel
  host/c32/c32.elf`). The demo is 1172 bytes + 1036 bss.

## Load sequence

1. `_main`: `install_hooks` (NASM hooks), `protect_image`, then **`c32_load`**
   (`host/c/c32_host.c`, 64-bit C).
2. `c32_load` checks the header (`struct c32_header`, `host/c32/c32_abi.h`: magic, base,
   sizes, start, imports, exports — the first bytes of the image, section `.c32.head`),
   maps and copies the image, zeroes `.bss`.
3. Binds every host service the image imports to a 32-bit import stub (`new_slot("c32",
   name)`, the same stubs `gta2.exe`'s IAT uses), writing the stub address into the image.
4. Makes the game's `.text` (`0x3F1000-0x56E000`) `rwx`, `call32`s the image's `c32_start`
   once, makes it `r-x` again. `c32_start` runs every `C32_INIT(fn)` — that is where hooks
   are installed.

`c32_load` runs after `protect_image` on purpose: before it the game image is not
executable, and the very first `c32_log` calls the game's `vsprintf` (measured: SIGBUS at
`0x4D7FE6`, `cs 0x87`).

## ABI

C32 and MSVC agree on what matters for i386: arguments on the stack right to left, `eax`
(`edx:eax`) return, `ebx esi edi ebp` callee-saved, direction flag clear. Conventions come
from `gta2_types.h`'s macros, which are real attributes for `i386-pc-none-elf`:
`G2_CDECL`, `G2_STDCALL` (callee pops), `G2_FASTCALL` (`ecx`, `edx`), `G2_THISCALL`
(`this` in `ecx`, callee pops). A C32 function with the game's convention *is* a valid game
function: `hk_driver_enter` below disassembles to `mov esi, ecx; ... ret 4`, exactly what
`Car_OnDriverEnter` is.

`va_list` is `char*` on both sides, so a C32 `va_list` can be handed to the game's
`vsprintf`.

## Calling game functions

`GAME_FN(ret, convention, name, va, (params))` declares a constant function pointer; clang
emits a direct `call va` for it. The three conventions of the demo:

```c
#include "c32.h"
GAME_FN(void, G2_THISCALL, ChangeMoney, 0x421990, (Player *self, int amount));   /* ret 4 */
GAME_FN(uint32_t, G2_FASTCALL, Player_IsLocal, 0x41DC70, (Player *self));        /* mov al,[ecx] */
GAME_FN(int, G2_CDECL, game_vsprintf, 0x4D7FE6, (char *buf, const char *fmt, va_list ap));

ChangeMoney(player, 333);                       /* mov ecx, player; push 333; call 0x421990 */
if (Player_IsLocal(player) & 0xFF) ...
```

Addresses come from `re/functions.csv` and are checked in the disassembly; cite both.

Struct fields: use `re/gta2_types.h` as is, and pin every field you rely on with
`C32_OFFSET(type, field, offset)` (a C99 negative-array-size check), so a re/ export that
moves a field breaks the build instead of the game:

```c
C32_OFFSET(Player, ped, 0x2C4);
C32_OFFSET(Ped, player, 0x15C);
C32_OFFSET(Car, driver, 0x54);
```

## No libc

There is none in the image. Use:

- the game's statically linked MSVC CRT (`game_vsprintf` in `c32.h`; `memcpy 0x4D9400`,
  `memset 0x4E02A0`, `memmove 0x4D6EB0` are bound by name in `c32.ld`, because clang emits
  those calls by itself for struct copies). Add others the same way, from `re/functions.csv`.
- host services, through the 32→64 import-stub path (one mode switch per call):

| Service | C32 side | Host handler (`host/c/c32_host.c`) |
|---|---|---|
| `log` | `c32_log(fmt, ...)`: formats with the game's `vsprintf` into 512 bytes on the stack, prints `c32: <text>` | `c32_svc_log` |
| `passenger_wanted` | `c32_passenger_wanted()`: `mods.passenger_enter` on and a Shift down (`di_keys`, host memory) | `c32_svc_passenger_wanted` |
| `foot_input` | `c32_foot_input(&in, on_foot)`: this tick's strafe keys and, on foot, the mouse (relative mode on/off, whole pixels since the last tick, stale backlog dropped); the host writes `struct c32_foot_input` (`c32_abi.h`) straight into C32 memory | `c32_svc_foot_input` |
| `ctl_on_foot` | `c32_ctl_on_foot(player, ped)`: gta2ctl's `goto` / `face` steering (`ctl_game.c`), after the mod's own writes | `c32_svc_ctl_on_foot` |

Adding a service: an entry in `imports[]` (`host/c32/rt.c`, the index enum), a `SHIM "name",
argbytes, _handler` row in `shimtab_c32` (`host/c32_blob.asm`), a C handler
`uint64_t handler(const uint32_t *args)` (`args` = the 32-bit stack arguments).

## Hooks

Installed from a `C32_INIT` function (the game's `.text` is writable only then). Both
check the original bytes first and log + return 0 on a mismatch.

**Entry detour** — the game function starts with `jmp fn`, and the returned trampoline is the
original (displaced bytes + `jmp` back):

```c
typedef void (G2_THISCALL *driver_enter_fn)(Car *self, Ped *ped);
static driver_enter_fn Car_OnDriverEnter;           /* the original */

static void G2_THISCALL hk_driver_enter(Car *car, Ped *ped)
{
    Car_OnDriverEnter(car, ped);                    /* C32 calls the original back */
    /* ... */
}

static void car_bonus_init(void)
{
    static const uint8_t orig[] = { 0x53, 0x8B, 0x5C, 0x24, 0x08 };  /* push ebx; mov ebx,[esp+8] */
    Car_OnDriverEnter = (driver_enter_fn)c32_detour(0x427A20, orig, sizeof orig,
                                                    (void *)hk_driver_enter);
}
C32_INIT(car_bonus_init);
```

The displaced bytes must be whole instructions (5..16 bytes) without relative operands
(`esp`-relative ones are fine: the trampoline runs on the caller's stack, like the
original).

**Call hook** — `c32_callhook(site, expected_target, fn)` retargets an `E8 call` and returns
its previous target as the original. If the site was already retargeted (a NASM `CALLHOOK`
in `w32_hooks.asm`), that hook comes back and is chained; the log line says so.
Not used by the demo; `passenger.c` uses three (verified at runtime).

**Mid-function hook** — `c32_midhook(va, orig, n, fn)` replaces `n` whole instructions
(5..16, no relative operands) inside a function with a `jmp` to a trampoline: `pushad; push
esp; call fn; add esp, 4; popad; <displaced bytes>; jmp va+n`. `fn(struct c32_regs *r)` sees
every register (`r->esp` = the function's `esp` at `va`, so its locals are `r->esp + off`)
and may change memory, not the registers; the displaced bytes run after it, so they see what
it wrote. The C32 counterpart of a NASM `JMPHOOK` that returns 0. `player_move.c` uses one
at `0x49AC76` (verified at runtime).

**Coexisting with NASM hooks.** A NASM `CALLHOOK` on a call site and a C32 detour on the
callee chain naturally: the NASM handler `call32`s the callee's VA, which now starts with
the detour. Measured with the Seq 53 pilot's `CALLHOOK 0x43F279` and the C32 detour on
`0x427A20` installed together.

## Exports (host → C32 data)

`C32_EXPORT(var)` records `{ "var", &var }` in `.c32.exports`; the host finds it by name
(`c32_find`) and reads/writes it directly — the image is identity-mapped. The demo's config
key and K menu row write `car_bonus` this way, no mode switch.

## Worked example: `host/c32/car_bonus.c`

+$N every time the local player gets into a car as the driver, an empty car or a jacked one.

- Seam: `Car_OnDriverEnter(Car*, Ped*)` @`0x427A20`, thiscall, `ret 4` (Seq 27; the only
  function that makes a ped a driver), detoured at its entry. Callers: `0x43F279`
  (`Ped_TickGameObjectAndSeatInCar`, end of the enter-car animation, driver branch) and `0x4A63A3`
  (`Player_TakeControlOfCar`, remote control).
- Checks: `ped->player` set, `Player_IsLocal`, `player->ped == ped` (skips the aux ped of
  the remote-control takeover — hypothesis from Seq 27's RE, no RC car was run),
  `car->driver == ped` after the original and not before it (one entry = one bonus, no
  frame debounce needed).
- Pays through `ChangeMoney` `0x421990` (raw add, HUD counter rolls up), logs
  `c32: car_enter_bonus +$333: car 59 (model 3), previous driver 0x0, money 0 -> 333`.
- Off by default: `mods: car_enter_bonus: 333` in `config.yaml` (0 = off), or K → Mods →
  "Car entry bonus" (both in `host/c/c32_host.c`).

Measured (2026-10-22, Downtown, 640×480): spawned parked car `$0 → $333`; carjack at a
traffic light `$50 → $383` (the $50 is the game's own jack reward) and getting back into
the same car `$383 → $716` (the scripted jack depends on traffic: not every run finds a
car); config off: nothing; K menu toggle in a run without config: `+$333`. In a jack the
old driver is already out of the car when `Car_OnDriverEnter` runs (`previous driver 0x0`).

## Second mod: `host/c32/passenger.c`

Shift+Enter gets in as a passenger through the game's own passenger path: three
`c32_callhook`s (0x4A7793, 0x43F280, 0x4A77E4), a host service for the Shift test, the switch
as a host byte in `config.c`'s key table. RE, call path and measurements:
[passenger.md](passenger.md). It also exercises `c32_callhook` at runtime (measured
2026-10-22), which the car bonus did not.

## Called by the host every frame: the world overlays

`host/c32/debug_paths.c` and `debug_roads.c` (K menu Ped paths / Road network,
[debug-menu.md](debug-menu.md) "World overlays") are not hooks: the host's `DM_FRAME` hook
`call32`s an exported C32 function once a frame (`C32_EXPORT(dp_draw)` works for functions
too; `call32` restores `esp` itself, so any convention will do, stdcall is used) and reads the
counters back from an exported struct. Inside, thousands of `WorldPointToScreen` /
`DrawFlatRect2D` calls a frame are plain `call`s (`overlay.c`). Two things learned:

- Out-parameters for game calls can be C32 locals: the stack is the game's, below 4 GB.
- `float` arguments go through x87 (`fild` / `fstp`, `-mno-sse`), exact for pixel ints; for
  the same rounding as NASM's x87 code, inline asm with the same instruction sequence
  (`debug_paths.c` `heading`).

## Third mod: `host/c32/player_move.c`

On-foot strafe (Q / E) and mouse turning, through the game's own walker and its collision
(analysis: `docs/re/ped-movement-collision.md` §6). Ported from `host/player_move.asm`
(Seq 62): a `c32_callhook` on `Player_MoveOnFoot`'s call site `0x4A7901` and a
`c32_midhook` at `0x49AC76` in `PedGameObject_StateWalk`. The host keeps everything that is
not game logic: the `controls:` config bytes and their log line (`pm_report`), the K menu
root rows "Mouse turning" / "Strafe (Q/E)", the keyboard and the SDL mouse (service
`foot_input`), and gta2ctl's steering, which must run after the mod's writes (service
`ctl_on_foot`). Two mode switches per tick. Test: `tests/ctl/player_move.sh` (walls stop a
strafe, diagonals, mouse turning with `gta2ctl mouse`, both off = vanilla); its per-tick
trajectory matched the NASM version's exactly.

## Pitfalls

- **Never write data on a page that holds code** (Rosetta). Rosetta translates x86 code
  per page and treats any store into such a page as self-modifying code. The hook
  trampolines used to be a `.bss` array next to ordinary variables: once a module stored to a
  neighbour every frame (`emergency.c`'s frame counter), the `Car_OnDriverEnter` trampoline
  (`car_bonus.c`) jumped into garbage the moment the player sat in a car (`signal 11, addr
  0x8fa`, esp in host memory; bisected and confirmed 2026-10-23, Seq 60). Since then the
  trampolines live in `.c32.tramp` on pages of their own and `.data`/`.bss` start on a fresh
  page (`c32.ld`); keep anything written at run time out of `.text` / `.c32.tramp`.
- **`.text` not executable before `protect_image`** — see "Load sequence".
- **Stack alignment**: game code calls you with `esp` 4-aligned. Without
  `-mstack-alignment=4` clang may assume 16 (harmless with `-mno-sse` today, a crash the day
  someone enables SSE and clang spills with `movaps`).
- **Small integers**: MSVC leaves garbage above `al`/`ax` in returns and arguments
  (`Player_IsLocal` is `mov al, [ecx]; ret`). clang i386 re-extends both itself (measured:
  `movzx` after the call and on the argument), but keep prototypes int-sized and mask,
  so it does not hinge on that.
- **`vsprintf` has no bound**: `c32_log` writes into 512 bytes; keep messages short, no
  unbounded `%s`.
- **No libc headers beyond the freestanding ones** (`stdint.h`, `stddef.h`, `stdarg.h`):
  `printf`, `strtol`, `snprintf` do not exist here. Config parsing and the K menu (64-bit
  host code) therefore stay on the host side (`c32_host.c`) and talk to C32 through
  exports.
- **Every hook must be installed at init.** Patching later needs `.text` writable again
  (a host service doing `mprotect` would do it; none exists yet).
- **Crashes** print like any game crash (`loader: signal 11, ... rip 0x0f0000xx cs 0x87`):
  an `rip` in `0x0F000000-0x0F100000` is C32 code; look it up in `c32/c32.map` or disassemble
  `c32/c32.elf` (it has symbols; lldb does not know the image).
- **Not re-entrant across threads** (nothing is; the game is single-threaded here).
